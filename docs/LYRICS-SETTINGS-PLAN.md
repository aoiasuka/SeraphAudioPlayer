# 歌词设置后续待办（v0.6.0 之后）

日期：2026-09-17。v0.6.0 已落地歌词设置五项、AMLL TTML 在线逐字歌词、繁体转换（Rust zhconv，写入前转换）、排除规则（**Rust regex 编译匹配**，后端回传前打 `hidden` 标记，规则变更广播 `seraph://lyrics-rules-updated` 让主窗口与任务栏重拉）、预设 / 自定义两种 DB 地址模式、**增强型 LRC 逐字解析**（`<mm:ss.xxx>` 行内标签 → `words` / `end`，随 offset 校正）、**本地歌词目录匹配**（`艺术家 - 曲名 (网易云ID).lrc`，切歌无歌词时自动匹配写入）、**文件名网易云 ID 复用为 AMLL 查找键**（`ImportedTrack.lyrics_lookup_keys`，在线匹配时直取 TTML）。本文只保留原规划中**尚未实现**的部分；已完成部分的终态见 `CLAUDE.md`「歌词设置与 TTML 逐字歌词」节。

## 1. 歌词模型

- 现状：`LyricLine = {time, text, end?, words?, translation?, roman?, hidden?}`，时间为秒；LRC / 增强型 LRC / TTML 会填 `words`，QRC / KRC / YRC 仍压平为行级。
- 待做：
  - 统一为 `LyricDocument`（毫秒整数、`schemaVersion`、`format` / `sync` 标记、来源与 `providerTrackId` 结构化字段、`speakerId`、多语言译文数组），配套存储清单版本升级、旧格式兼容读取与迁移备份。
  - `LyricBinding` 完整版：现只有 `lyrics_lookup_keys: Vec<String>` 记平台 ID，尚无自动 / 手动选择状态、来源与版本。
  - QRC / KRC / YRC 解析保留已有逐词时间（三者本身带逐字标签，现丢弃）。
  - LRC 缺结束时间时用下一组开始时间推导展示区间并标记为推导值；纯文本明确 `sync: none`（现每行合成 4 秒）。
  - 重叠句 / 背景人声：时间定位支持多个活动区间，滚动单独选主句；现仍是"二分找最后一个开始时间"的单活动行。

## 2. 歌词来源策略

- 用户手动导入或明确应用的歌词视为固定选择，自动请求不得替换；提供"恢复自动匹配"。本地歌词目录匹配现只在曲库**没有**歌词时触发，不会覆盖已有歌词，但也没有"重新从目录匹配"的手动入口。
- 自动模式先展示现有歌词，启用在线 TTML 后在身份与版本匹配可靠时原子切换到 TTML；未收录 / 解析失败 / 网络失败继续用原歌词。
- 普通歌词回退顺序：同名外部歌词 → 歌词目录 → 内嵌 → 在线同步 → 纯文本；已有可用歌词不重复三源查询。
- "自动"先比匹配度（标题 / 歌手 / 版本 / 时长），再比同步能力与译文质量；指定平台优先只在合格候选内提权。
- `apply_online_lyrics` 接受候选身份与文档，应用后保留来源信息（现只剩一份无来源的行数组，且 AMLL 命中的 `ttml_lookup_keys` 没有回写到曲目）。
- 老曲库无法区分手动 / 自动时，先把已有歌词作为保留选择。

## 3. TTML

- 本地 `.ttml` **手动导入**（歌词稿「导入」按钮的扩展名列表尚未加 `.ttml`；歌词目录匹配已支持 `.ttml`）与同名 sidecar 发现（`find_lyrics_file` 扩展名列表尚未加）。
- 高亮在暂停、跳转、切歌、窗口重新显示时重新对齐（现只以 store `currentTime` 为锚外推）。
- 在线接入的匹配升级：按标题 / 歌手 / 专辑 / 时长搜索，保留 Live / Remaster / 翻唱等版本信息参与匹配；高置信度才自动绑定，模糊结果走候选预览。
- 接入 AMLL 官方 API（amll-dev/amll-ttml-api，文档 https://amll.dev/reference/http-api/overview）作为索引适配器，实现按歌名检索而不只依赖三源候选 ID 与本地文件名 ID；接入前核对其字段与更新方式。
- 数据库未收录时界面说明 TTML 匹配结果，与"没有歌词"区分。
- 地址弹窗"测试连接"：区分地址不可达、目标未收录、返回 HTML、无效 XML、不支持的 TTML 内容。
- TTML 新路径补总词段数、嵌套深度与时间范围限制（现只有 2 MB 文件上限与行数 / 行长收口）。

## 4. 繁体转换

- 现状：Rust 侧写入前按 CJK 字符范围整体转换 text / translation / words，已存歌词不回溯，关开关不逆转。
- 待做（若改为显示投影方案）：
  - 前端共享纯函数 / Worker 做显示层转换，保留原文，关闭即恢复；按"文档版本 + 转换模式"缓存，进度变化不重算。
  - 依据语言标记处理中文原文与中文译文；缺标记时保守判断，避免改日文汉字与音译。
  - 逐字歌词校验整句转换结果与词段映射；无法对应时该句降级为行级高亮并保留行时间。

## 5. 排除规则

- 命中预览：编辑界面展示受影响歌词行（后端已有 `hidden` 标记，可直接把当前曲目命中行列出来）。
- 全部被过滤时显示"歌词已被排除规则隐藏"并提供关闭规则入口，与"没有歌词"区分。
- 可选"制作信息"预设（如 `^(作词|作曲|编曲)\s*[:：]`），默认不启用。
- 隐藏句播放期间不延长上一句、不改变后续点击定位时间（现前端按 `hidden` 过滤后再分组，隐藏句的时间区间被并入上一句）。
- 后续高级选项：仅隐藏译文。

## 6. 设置、缓存与多窗口一致性

- 排除规则变更已有独立事件；繁体开关与译文 / 音译显示开关仍没有，任务栏条对这两项不即时同步。
- Rust 接收带递增版本的设置快照作为网络与过滤决策依据（现排除规则是无版本的整体替换）；任务栏新建先取快照再按版本接受事件。
- 在线 TTML 缓存：保存原始内容与解析版本，键含数据库配置身份、平台、歌曲 ID、格式、解析器版本；有效缓存优先、到期复验；"未收录"短期负缓存，网络失败不作长期记录；已选定歌词与可清理缓存分开。
- 异步结果携带 `trackId`、请求序号、歌词版本与设置版本：快速切歌、切回同曲、改镜像、手动应用都使旧请求失去发布资格；后端写入也核对版本；相同请求合并，主窗口与任务栏不重复下载。`find_local_lyrics` 现只靠前端切歌前后 `currentTrack` 比对做迟到保护。
- 歌词目录匹配现只扫一层、不递归；目录变更后不会对已播放过的无歌词曲目重扫。
- 界面自救重置入口（歌词设置一键恢复默认）。
