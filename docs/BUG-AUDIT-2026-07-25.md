## 一、高危（1 条）

### H-1【确定】EQ 数据无消毒 → 坏数据持久化 → 启动白屏死循环

**位置**：`src/components/pages/main-pages/EqPage.tsx:137-147,583`、`src/store/eq.ts:121-129,154-157`、`src/main.tsx`、`src/lib/eqResponse.ts:22`

三条坏数据入口，全部绕过数值校验直达持久化 store：

1. **JSON 预设导入**（EqPage.tsx:137-147）：仅校验 `Array.isArray(parsed.bands)`；`preamp` 为字符串时经 `parsed.preamp ?? 0` 原样放行（`??` 只拦 null/undefined）；band 的 `freq/gain/q/kind` 字段类型完全不校验。
2. **高级编辑输入框**（EqPage.tsx:574-596）：清空 freq/gain/q 任一输入框 → `Number.parseFloat("") = NaN` → `updateBand` 直接 `{ ...band, ...patch }` 合入 store（对比 `setBandGain` 有 clamp，此处无）。
3. **配置备份导入**（configTransfer.ts:184-189）：对 `seraph-eq-state` 整包写入 localStorage，零字段校验。

**崩溃链**：NaN 当场渲染为 "NaN" 不崩，但 persist 时 `JSON.stringify(NaN)` 序列化为 `null` → 重启水合后 `eq.preamp.toFixed(1)`（EqPage.tsx:286-287）或 `band.gain.toFixed(1)` 对 null/字符串抛 TypeError → `main.tsx` 无 ErrorBoundary，React 卸载整棵树 → **白屏**。且 `activeView:"eq"` 同被 player store 持久化，重启后直接渲染 EqPage → **每次启动都白屏，只能手动清 localStorage 自救**。

**次生影响**：NaN freq 使前端频响曲线 SVG path 整条失效（`eqResponse.ts:22` 对 q/gain 有 `Number.isFinite` 兜底、唯独 freq 没有）；NaN→null 经 Tauri invoke 到后端，`EqBand` 的 f32 必填字段 serde 反序列化直接 Err → `set_dsp_settings` 此后持续失败且仅 console.warn —— **EQ/crossfeed 在引擎侧静默失效**（后端 `eq.rs` 的 NaN 兜底根本轮不到执行）。

**修复建议**：`setBands`/`updateBand` 入口做 isFinite + clamp + 结构校验；`eqResponse.ts` 给 freq 补兜底；`main.tsx` 加 ErrorBoundary 根治死循环一类问题；JSON 导入分支同时补 `MAX_BANDS` 上限与"导入后自动启用"（当前仅 APO 分支有）。

## 二、中危（19 条）

### 播放引擎与系统集成

**M-1【确定】SMTC 媒体键 resume 假成功 —— UI 显示播放中但无声**
`crates/seraph-audio/src/engine.rs:530-538` + `src-tauri/src/smtc.rs:269-277`。`engine.resume()` 只检查 session 存在、不检查 `shared.stopped`。队列仅 1 首且未开循环时自然播完后，engine.session 残留（stopped=true 但未被清理），按媒体键播放 → `smtc_play` 先试 `audio.resume()` → 假成功并广播 `PlaybackResumed` → 前端与系统浮窗显示"播放中"，实际解码/渲染线程均已退出，无声也无进度。前端 UI 按钮不受影响（`sendPlayCommand` 恒带 path 走 `play_file` 的 can_resume 防护）。修复：`resume()` 检查 stopped 返回 Err，让 `smtc_play` 落到 `play_current_track` 重建会话。

**M-2【确定】分析页 resize 面板反向位移**
`src/lib/analysis/gridLayout.ts:52-58,154-165`。`resizeItem` 声称"左上角固定"，但复用 `clampRect` 的 `x = Math.min(GRID_COLS - w, x)`：默认布局 spectrum/scope/field 全部贴右缘（x+w=12），编辑模式向右拖 resize 手柄 → 面板左移一格并加宽、连锁下推左侧面板，继续拖持续左移。垂直方向同理。修复：resize 路径改为 `w ≤ 12 - cur.x`、`h ≤ 12 - cur.y`。

**M-3【确定】暂停后声场散点云高亮冻结**
`src/lib/analysis/view.ts:204-221`。断流衰减分支处理了频谱/电平/相关度/示波器，唯独遗漏 `view.stereo.pts`：暂停后其他仪表全部优雅归零，声场面板散点以 0.8 不透明度定格高亮（配合 AnalysisPage trail 只在引用变化时推进），与"断流后所有量优雅衰减"的设计注释直接矛盾。

**M-4【确定】侧栏频谱每帧重建 canvas backing store**
`src/components/sidebar/SpectrumPanel.tsx:46-49`。`canvas.width !== width * ratio` 用浮点比较：canvas.width 是 ToUint32 截断的整数，Windows 125%/150% 缩放下 `width*ratio` 非整数时恒不等 → 每帧重设宽高、重分配位图并清空画布，抵消了"暂停停 RAF 省电"的设计。修复：同 `render.ts:116` 用 `Math.round`。

`src-tauri/src/ipc/playlist_io.rs:44`。导入只走 `from_utf8_lossy`，而老播放器（千千静听、中文 foobar2000）导出的 .m3u 是 GBK：中文路径变 U+FFFD → `is_file()` 全失败 → 导入 0 首且提示误导。歌词模块有完整 GBK 兜底（lyrics.rs:516）可复用。

**M-8【很可能】M3U8 路径回映射弱规范化，旧库文件建歌单静默丢曲**
`libraryActions.ts:255-260` + `trackIdentity.ts:12-14`。前端映射键只 trim+lowercase、不归一分隔符；后端 canonicalize 去重且重导入返回旧写法 path。清单用正斜杠（foobar2000 等跨平台工具导出常见）而库内是反斜杠时映射 miss → 曲目被歌单静默丢弃，整单旧库文件时误报"导入失败"。

### 解码与响度分析

**M-19【可疑】mono 输入的 LUFS 读数比 BS.1770 规范高 +3.0 LU**
`crates/seraph-visualizer/src/analysis.rs:247-291`。响度计把单声道样本复制为 L/R 两路后将两路 K 加权能量**求和**：能量翻倍，momentary/short-term/integrated LUFS 全部系统性 +3.01 LU（BS.1770-4 对 mono 定义为单通道 G=1.0）。文件头注释声明"mono 复制为双声道"是为 peak/相关度/散点服务的有意设计，但响度积分共享了同一条累加路径，+3 dB 是副作用。触发条件：tap 处 `channels==1`（播放单声道音频且渲染链未先上混）——`ipc/visualizer.rs:95` 的 `channels.max(1)` 表明该分支可达；若渲染管线恒先上混立体声则不可达（此时 +3 dB 反而符合规范），故标可疑。表现：分析页 LUFS 与 foobar2000 R128 / ffmpeg loudnorm 恒差 +3 dB。
