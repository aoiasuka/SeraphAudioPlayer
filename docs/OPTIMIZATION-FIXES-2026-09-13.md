## 2. 关键行为变化

### 2.1 播放队列与歌词

[前端队列同步](../src/store/player/queueSync.ts) 使用 `clientId`、内容 `revision` 和请求 `sequence`；[后端队列](../src-tauri/src/state.rs) 校验序号和版本。相同最新在途请求共用 Promise，已确认的重复状态不再发送。只补入歌词时沿用原队列内容版本；标题、封面等队列元数据改变后重新同步完整内容。A→B→A 的快速切换不会复用已经过期的 A 请求。

[曲库快照](../src-tauri/src/ipc/library/snapshot.rs) 维护 `trackId → index`，单曲查询只克隆命中项。[列表命令](../src-tauri/src/ipc/library/commands.rs) 默认保留完整返回的兼容行为；主窗口显式传 `includeLyrics: false`，序列化借用快照内的元数据。`lyricsLoaded` 区分“尚未读取”和“确实没有歌词”；[播放 Hook](../src/hooks/usePlayback.ts) 按需补入当前曲目的歌词，并防止迟到结果覆盖切歌或用户修改。

列表仍一次传输全部元数据。歌词首次补入需要检查队列元数据是否一致，该检查仍为 O(N)，但请求体不再包含全库。前端歌单引用变化也会使搜索排序缓存失效。

### 2.2 曲库存储格式及恢复

[存储模块](../src-tauri/src/ipc/library/storage.rs) 采用以下文件：

| 文件 | 用途 |
| --- | --- |
| `library-snapshot.json` | 当前已提交清单，引用一份元数据和一份歌词文件 |
| `library-snapshot.previous.json` | 上一份完整清单 |
| `library-snapshots/<代次>-tracks.json` | 不可变元数据文件 |
| `library-snapshots/<代次>-lyrics.json` | 不可变歌词文件 |
| 原 `library-cache.json` / `library-lyrics.json` | 首次迁移前的旧格式备份，保留原内容 |

提交先写新文件并 `sync_all`，最后以同卷 rename 替换当前清单。只有元数据改变时复用歌词文件，只有歌词改变时复用元数据文件；两者都没变化时不提交，也不更新内存快照。磁盘冷读取、恢复、提交和旧快照清理通过同一曲库锁串行化。清理只匹配本模块生成的数字代次文件名，保留当前/上一版引用和 `.corrupt` 现场。

当前清单或引用文件无法读取时，仅在上一份清单及其两个文件均能解析后恢复上一版；恢复可能丢失最近一次已提交的变更。损坏文件尽可能复制为 `.corrupt`，备份失败会保留原现场并停止覆盖。旧格式歌词文件损坏时明确报错；遇到未来版本清单也停止读写。上一版不可用时返回错误，不把损坏曲库当作空库写回。

**降级注意：旧程序不认识新清单，只会看到迁移前保留的旧 JSON。** 启用新版并产生新变更后，如需回到旧版，应先备份整个应用数据目录并安排格式转换；保留旧文件不代表旧程序能读取迁移后的更新。本轮没有运行实际用户曲库迁移，也没有自动执行降级转换。

当前设计提供元数据/歌词两部分的提交一致性；修改一首歌词仍会重写歌词文件。故障注入测试覆盖四个写入阶段失败、损坏清单/歌词、未来格式拒绝与完整上一版恢复；这些检查未模拟机器断电或存储设备故障。

### 2.3 可视化与界面

[可视化服务](../src-tauri/src/visualizer_service.rs) 在首次需求时启动专用线程，以约 33 ms 的周期计算；没有续租需求 250 ms 后休眠。侧栏只启用 2048 点/48 柱 FFT，分析页按需开启频谱、响度、电平、声场和示波器。IPC 读取已完成帧，发布前再次检查请求代次和重置状态。

[串行轮询器](../src/lib/serialPoller.ts) 保证跨页面最多一个可视化 IPC 在途；隐藏窗口暂停定时器和动画帧，迟到响应按请求身份丢弃。分析页编辑布局或关闭全部仪表时停止取帧。

响度统计采用页面内实际采样语义：只有开启响度仪表时输入的数据参与积分；暂停、隐藏或重开仪表时清理连续窗口，同一会话保留积分和最大值；切歌或离开页面后重新进入会重置会话。页面已显示该含义。原有约 5.56 小时的历史上限仍保留，超过上限后反映最近窗口。

[VirtualGrid](../src/components/pages/main-pages/VirtualGrid.tsx) 按测得的列数和行高渲染可见卡片及前后各两行，支持方向键、Home/End；艺术家文本截断以保持等高。封面目前仍使用原图，尚未建立缩略图缓存。字体处理在 PostCSS 早期移除 WOFF，避免 Vite 已收集旧格式资源后留下无用文件。

### 2.4 下载、日志与环境

[收藏夹取消令牌](../src-tauri/src/ipc/bilibili/cancellation.rs) 与任务 ID 绑定，同一时刻仅允许一个收藏夹批次；旧取消请求或旧进度事件不影响新任务。[下载代码](../src-tauri/src/ipc/bilibili/import_audio.rs) 使用异步音频正文写入，网络等待可被取消；ffmpeg 定期检查取消，结束子进程后清理当前临时文件。已经入库的曲目保留。取消仍需等待正在进行的磁盘写入/flush 和必要的入库收尾，不能将 25 ms 检查周期视为任何设备上的取消延迟保证。

[诊断日志](../src-tauri/src/diagnostics.rs) 写入 Tauri `app_log_dir` 下的 `seraph.log`，单文件约 1 MiB，最多保留 3 个轮转文件。正常路径通过 256 条有界队列在后台写入；单条记录截断至约 16 KiB，满队列丢弃诊断记录以避免阻塞业务。写文件失败后保留 stderr 输出。Cookie、Authorization、常见令牌字段和 HTTP URL 中的凭据/查询/片段有脱敏处理，并有回归测试；新增日志仍需避免主动记录敏感载荷。

音频回调只累计缺样帧和 tap 锁竞争等轻量指标，由事件线程间隔汇总。**缺样帧包含起播、跳转和曲尾；tap 覆盖样本还可能来自未显示可视化期间，均不能直接等同于听到断音。** 本轮没有调整音频设备缓冲、独占输出策略或原有实时线程防护。

CI 和发布使用 Node `24.14.0`、Rust `1.98.1`，Cargo 验证/发布传递 `--locked`，并设置 `RUSTUP_TOOLCHAIN=1.98.1`，避免仓库的 `stable` 配置覆盖 CI 版本。新增 `.node-version`。本地 `rust-toolchain.toml` 仍为 `stable`，本机实际版本与 CI 一致；本轮未安装离线环境中缺少的具名工具链。`cargo-audit` 的工具版本固定仍待完成。
